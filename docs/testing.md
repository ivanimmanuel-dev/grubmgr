# Testing and release gates

## Automated checks

```sh
go test ./...
go vet ./...
go mod verify
go run ./tools/checklicenses
test -z "$(gofmt -l cmd internal tools)"
go build -o grubmgr ./cmd/grubmgr
```

CI runs Linux and Windows, with Linux race detection. The ordinary test suite uses temporary synthetic roots. No test invokes GRUB, QEMU, a community installer, or a privileged helper. HTTPS tests use an in-process loopback TLS server; a sandbox that prohibits local sockets needs that test run outside its network restriction. No public theme is downloaded by the test suite.

On Windows, use a short writable temporary directory when the sandbox's default temporary path is exceptionally long:

```powershell
New-Item -ItemType Directory -Force work/test-tmp | Out-Null
$env:TEMP = Join-Path $PWD work/test-tmp
$env:TMP = $env:TEMP
go test ./...
```

Case-collision directory tests are skipped on case-insensitive Windows filesystems; equivalent ZIP cases still run. Symlink tests skip when the Windows account cannot create links; they run on Linux CI. Hardlink tests run wherever the filesystem permits them. See the delivery verification report for actual runs and skips, rather than treating a configured CI job as a completed remote run.

## Coverage by behavior

| Area | Test evidence |
| --- | --- |
| CLI workflow | doctor → info → fetch → validate → install plan/apply → switch plan/apply → status/history; JSON and exit codes |
| Detection | Debian conventional, Arch conventional, Fedora EFI forwarding stub, non-GRUB and ambiguous roots; no host fallback; doctor read-only |
| Ingestion | Duplicate/case/conflicting archive paths, traversal, absolute/drive/backslash names, links/devices, count/per-file/total limits, TAR, HTTPS digests and downgrade refusal |
| Package identity | Idempotent fetch, tamper detection, ambiguous roots, exact immutable revision selection, notice retention |
| Validation | Original simple theme, nested palette PNG, missing/case-mismatched asset, broken image, script payload, missing font, PF2 framing/name, multiple variants |
| Planning | Root fingerprint, stale state, read-only tree snapshots, unknown-license refusal, unsupported backends |
| Transactions | Every normal phase and commit boundary failure, install without switch, switch/variant/remove/later rollback, active asset retention and cleanup of newly staged assets |
| Recovery | Interruption after each pre-commit durable phase, retryable restore failure, conflicting external edits, pending-journal refusal |
| Boot inventory | Later rollback preserves a new kernel entry added after the original transaction |
| Containment | Symlink escape refusal and hardlink targets cannot change outside files |
| Licenses | Pinned module/version inventory and full preserved notice hash checks; `go mod verify` |

Fixtures under `fixtures/` are original synthetic text. Archive, image and PF2 samples are generated by tests to keep provenance clear and avoid storing harmful executable payloads. `internal/catalog/demo` supplies the original multi-variant sample. A fixture can be copied into `work/`; do not test activation against a real mounted system.

## Recovery demo

Failure/interruption injection is a Go test dependency (`transaction.Faults`), not a package manifest field or a public activation override. Run focused cases with:

```sh
go test -v ./internal/transaction -run 'TestFailuresEveryPhase|TestSwitchFailuresRetainActiveAssets|TestInterruptedRecovery|TestRecoveryFailureAndDrift'
```

For an actual interrupted **fixture** process: verify it has stopped, preserve the root and SQLite files, remove only its stale `.grubmgr/apply.lock` and `.grubmgr/state/operation.lock` if they remain, then run `grubmgr --root ROOT recover`. If it reports conflicting hashes, inspect the recorded snapshots and restore the fixture manually; do not discard the journal or claim automatic success. `recover` outputs the recovered journal/snapshots, which may include configuration text.
